# 发票信息识别及整理

本技能目录结构:

```txt
skills/invoice-processing/
├── SKILL.md
├── scripts/gen_receipt.py
├── scripts/gen_summary.py
├── references/环境准备.md
└── assets/
    ├── 报销申请单模版.docx
    ├── 月度汇总模版.xlsx                   # 含 2026 年 6 月示例数据, 只是版式参考, 不是本月数据
    └── 曹英辰报销申请单中轻（雄安）2026-7-9（请款申请未报）.docx  # 已完成示例
```

## 通用原则

执行本技能的过程中, 遇到任何存疑的地方 (信息缺失、模糊、矛盾或不确定如何处理), 都必须停下询问用户, 确认后再继续。

识别与分类一律以发票内容为准, 忽略发票的文件名; 报销单中的人员归属以人员文件夹名称为准。

源发票目录是当月目录, 下设人员文件夹, 发票原件放在其中 (类别子文件夹由步骤② 建立)。所有生成的报销单和月度汇总文件均直接保存在源发票目录下。

## 步骤① 识别信息

从每张发票/收据中抽取以下 4 项信息:

- 发票编号
- 发票日期
- 购买方名称
- 总金额

总金额同时识别大写和小写价税合计, 两者一致才采信; 若不一致, 停下询问用户以哪个为准。

完成判据: 每张发票都抽齐上述 4 项; 无法抽取的逐条记下原因。

## 步骤② 分类入文件夹

文件夹结构固定为两级: 人员文件夹 / 类别子文件夹。不存在的自动新增。每张发票只归入一个类别, **移动**到对应人员的对应类别子文件夹 (移动而非复制, 不保留副本)。

- 餐饮费: 餐费
- 办公费: 除差旅费/交通费/快递费/餐饮费外的一切发票均归入此类, 如咖啡、水果、饮料、办公用品、名片/logo/标书制作费等
- 差旅费: 机票发票、机票行程单、高铁票、火车票、住宿费、退票费等
- 交通费: 打车费
- 快递费: 快递费

完成判据: 每张发票都归入且仅归入一个类别子文件夹, 且位于对应人员文件夹下; 人员文件夹根部不再留有未归档的发票; 无法分类的逐条记下原因。

## 步骤③ 排序逻辑

步骤④ 写入报销单时的排列规则, 本身不产生文件 (步骤⑤ 的排序由 `scripts/gen_summary.py` 内部完成)。

在每个人、每个类别内:

1. 发票日期按 "增序" 排列 (即从旧到新，数值最小的日期排最前)
2. 发票金额按 "增序" 排列 (即从小到大的数字)
3. 发票编号按 "增序" 排列 (即从小编号到大编号)

## 步骤④ 生成报销单

为每个 "姓名+购买方" 组合各生成一份 .docx 报销申请单。

- 文件名为 "姓名" + "报销申请单" + "购买方名称" + "生成当天日期", 日期格式如示例 "2026-7-9"; 示例中的 "（请款申请未报）" 等备注后缀仅在有需要时附加
- 发票按步骤②的类别、步骤③的排序逻辑排列后, 再写入模版
- 生成时使用 `scripts/gen_receipt.py` (见下)
- 有多少发票就填多少条记录, 不合并、不分离
- 每条记录附一句说明, 写法参照 `assets/` 中已完成示例 (如 "机票 北京-厦门 SC2130")
- 实际金额一律以步骤①从发票中识别到的总金额为准, 不自行估算或改值
- 金额大写由脚本从总金额转换, 不要自己写

### 环境准备: Python 安装

Python 与依赖未就绪时, 安装与验证步骤见 `references/环境准备.md`。以下命令按 macOS 写, Windows 把 `python3` 换成 `python`。

### 使用生成脚本

`scripts/gen_receipt.py` 按 `assets/报销申请单模版.docx` 生成报销单, 用法:

```bash
python3 scripts/gen_receipt.py --data data.json --source-dir "源发票目录" --output "输出文件名.docx" [--template 模版路径]
```

`--data` 为 JSON 文件, 结构见 `scripts/gen_receipt.py` 顶部说明。版式、列宽、类别的排版顺序与序号由模版决定, `items` 怎么排都不影响结果; 填入内容的字体字号由脚本固定。脚本会打印该单的合计金额, 步骤⑥ 要用。

### 快递费

运单记录为独立文件。若存在运单记录, 快递费发票需与之逐笔一一对应, 并写明始发地与送达地。

完成判据: 每个 "姓名+购买方" 组合各生成一份且直接位于源发票目录下, 记录数与发票数一致, 每条记录都有说明; 各类别内记录满足步骤③的排序; 无法处理的发票/收据逐条记下原因。

## 步骤⑤ 月度汇总

把当月全部发票平铺成 records 交给 `scripts/gen_summary.py`: 每张发票一条, 含人员、类别、发票编号、日期、总金额, 并附一句简要说明 (写法同步骤④)。

分人员、分类别、组内排序、各组合计、人员之间的空行, 全部由脚本按 `assets/月度汇总模版.xlsx` 的版式生成。

`scripts/gen_summary.py` 用法:

```bash
python3 scripts/gen_summary.py --data data.json --source-dir "源发票目录" --output "月度汇总.xlsx" [--template 模版路径]
```

`--data` 为 JSON 文件, 结构见 `scripts/gen_summary.py` 顶部说明。脚本会打印当月合计金额, 步骤⑥ 要用。

完成判据: 当月全部发票都出现在 records 中, 每条都有简要说明; 汇总文件直接位于源发票目录下。

## 步骤⑥ 交叉核对

在本次实际执行的步骤范围内核对 (未执行的步骤不参与核对):

- 张数: 识别的发票数 = 分类的发票数 = 报销单记录数 = 汇总的发票数
- 金额: 各报销单打印的合计之和 = 月度汇总打印的合计

任一项不一致则停下查明原因并询问用户。

## 最后

汇总并逐条列出所有记下的问题 (未能识别的信息、无法分类的发票/收据、无法处理的发票) 及其原因。
